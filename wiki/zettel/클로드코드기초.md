## 클로드 코드란

터미널에서 내 폴더의 파일을 직접 읽고, 쓰고, 프로그램을 실행하는 클로드. 파일을 올리고 내려받는 왕복이 없어 "저 폴더의 강의노트를 읽고 정리해 줘"가 한 문장으로 끝난다 (02-클로드코드와위키.pdf p.3).

## 웹 대화창과의 차이

| | 웹 대화창 | 클로드 코드 |
|---|---|---|
| 파일 주기 | 하나씩 올리기 | 폴더를 가리키면 알아서 읽음 |
| 결과 받기 | 화면에서 복사 | 파일로 저장됨 |
| 중간 산출물 | 남지 않음 | 폴더에 쌓임 |
| 다시 하기 | 처음부터 다시 설명 | 규칙을 적어 두면 재현 |
| 안전 | 할 것이 없음 | 무엇을 허용할지 내가 정함 |

(p.4)

## 작업 폴더 원칙

클로드를 연 폴더가 이번 작업의 전부다. 이 폴더 안만 읽고 쓰며 밖은 보지 않는다. CLAUDE.md·설정·스킬이 모두 이 폴더 기준이고, 폴더 하나 = 프로젝트 하나다. 바탕화면이나 문서 폴더 전체에서 열면 안 되고, 중요한 파일이 있는 곳에서 시작하면 되돌릴 수 없다 (p.6).

## 에이전트 루프

대화창은 "내 질문 → 클로드 → 답 하나"로 끝나고 파일을 스스로 찾거나 한 일을 확인하지 않는다. 반면 클로드 코드는 지시 → 맥락 수집 → 도구 실행 → 결과 검증 → (어긋나면 맥락 수집으로 되돌아감) 의 루프를 스스로 여러 바퀴 돈다. 차이는 스스로 찾아 읽고, 한 일을 확인하고, 어긋나면 되돌아가는 것이다 (p.7–8).

쓰는 도구는 다섯 갈래: 읽기(파일·PDF·이미지), 쓰기(새 파일·부분 수정), 검색(이름과 내용), 실행(터미널 명령·파이썬), 웹(주소를 열어 읽기). 실행이 끼어 있어 승인을 물어본다 (p.8).

## 권한 모드

| 모드 | 동작 | 언제 쓰나 |
|---|---|---|
| 자동 auto | 묻지 않고 끝까지 함 | 되돌릴 수 있는 폴더에서만 |
| 수동 default | 쓰기·실행마다 승인을 물음 | 평소 |
| 편집 자동 수락 acceptEdits | 파일 편집은 자동, 그 밖은 물음 | 같은 손질을 여러 파일에 반복할 때 |
| 계획 plan | 읽기만 하고 할 일을 먼저 보여 줌 | 여러 파일을 한꺼번에 고치기 전 |

Shift+Tab으로 순환 (p.10).

## CLAUDE.md

매 세션 시작에 자동으로 읽히는 규칙 파일. `~/.claude/CLAUDE.md`(전역) < `./CLAUDE.md`(폴더, 공유 가능) < `./CLAUDE.local.md`(나만) 순으로 구체적인 것이 이긴다. 말로 한 규칙은 다음 대화에서 사라지지만, 파일에 적으면 매번 읽고 시작한다. `/init`으로 초안을 만들고 `/memory`로 고친다 (p.12).

## 컨텍스트와 세션 관리

컨텍스트(대화·읽은 파일·CLAUDE.md 전부)에는 한도가 있어 넘으면 오래된 것부터 요약으로 접힌다. 대화가 길어지면 `/compact`, 다른 일로 넘어가면 `/clear`, 얼마나 찼는지는 `/context`로 확인한다 (p.13). 세션이 끝나면 대화는 사라지고 파일만 남으므로 규칙은 CLAUDE.md에 적어 둔다 (p.14).

## 좋은 지시의 조건

1. 무엇을 어디서 — "고쳐 줘"가 아니라 "07-기술적분석.md의 표 두 번째 줄을 고쳐 줘"
2. 한 번에 하나 — 세 가지를 한 문장에 담으면 하나만 제대로 된다
3. 결과물의 형태를 정함 — "표로" · "마크다운 파일 하나로"
4. `@`로 파일(또는 폴더)을 가리킴

(p.15)

## 하지 말 것 셋

인증키·비밀번호를 대화창에 붙여 넣지 않는다(대화 기록·로그에 남음), `--dangerously-skip-permissions`로 권한을 통째로 건너뛰지 않는다, 되돌릴 수 없는 폴더에서 시작하지 않는다(위키는 my-wiki/ 안에서만) (p.17).

## 확인 필요

- `/rewind`, `claude --continue`/`--resume` 등 명령의 정확한 동작은 클로드 코드 버전에 따라 달라질 수 있음 — 강의노트는 "명령과 화면은 버전마다 달라진다. 막히면 /help"라고 명시 (p.36).
