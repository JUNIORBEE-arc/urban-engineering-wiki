## 핵심 주장

데이터 분석 도구는 R(2022) → 파이썬(2023~24) → 코랩+Gemini(2025) → 에이전틱 AI(2026) 순으로 바뀌어 왔고, 도구가 바뀔 때마다 "사람이 해야 하는 일"의 정의도 함께 바뀌었다 (01-왜AI와함께하는가.pdf p.5).

## 왜 코드를 읽지 않아도 되는 시대가 왔나

2025년까지는 AI에게 코드를 요청하면 요청과 맞지 않는 코드가 나오거나 실행 오류가 나는 경우가 있어, "직접 쓰지는 않더라도 읽고 이해할 수는 있어야 한다"고 가르쳤다 (p.8–10).

에이전틱 AI(클로드 코드, Codex 등)의 등장으로 코드 오류는 거의 사라졌고, 규칙화하기 힘든 요청이 아니면 대부분 수행하게 되어 사람이 코드를 짜거나 오류를 검토할 필요가 사실상 없어졌다 (p.11).

근거로 SWE-bench Verified(실제 GitHub 이슈 500건을 AI가 스스로 고쳐낸 비율) 수치가 제시된다: Claude 3 Opus 22% (2024.03) → 3.5 Sonnet 33% (2024.06) → 3.5 Sonnet 신형 49% (2024.10) → Opus 4 72.5% (2025.05) → Opus 4.5 80.9% (2025.11) (p.6). 이 수치는 Anthropic이 자사 모델에 대해 공개한 값으로, 측정 방식과 도구 설정이 판마다 달라 절대 비교에는 한계가 있다고 명시되어 있다 (p.6).

## 역량의 이동

| 시기 | 사람이 하던 일 |
|---|---|
| 2022~24 | 코드 작성 — 문법을 알고 직접 짠다 |
| 2025 | 코드 읽기 — AI가 짠 코드의 오류를 찾아낸다 |
| 2026~ | 로직 이해와 검증 — 분석의 논리가 맞는지 문서로 확인 |

"코드는 이제 AI의 일. 로직은 여전히 사람의 일. 그리고 문제정의도 여전히 사람의 일" (p.14–15).

## 코드 대신 로직 문서를 요구하라

코드(analysis.py)만 받으면 왜 특정 조건(예: 면적 60㎡ 이하 제외)을 걸었는지, 평균과 중앙값 중 무엇을 볼지 등 판단의 근거가 코드에 드러나지 않는다. 반면 로직을 문서로 요구하면 "대상 / 지표 / 요약" 각 단계에서 왜 그렇게 했는지가 문장으로 드러나 사람이 읽고 따질 수 있다 (p.12).

→ 이 수업의 원칙: **코드 대신 로직을 문서로 요구하고, 그 로직을 이해하고 검증한다.** "무엇을, 왜, 어떻게 계산했는가"를 설명하지 못하는 분석은 증거가 될 수 없다 (p.16).

## 데이터 → 증거 → 주장

주장은 데이터에서 곧바로 나오지 않는다. 데이터(수집한 숫자 그 자체) → [분석] → 증거(요약·비교·검정을 거쳐 뜻이 생긴 결과) → [논거] → 주장("이렇게 해야 한다", 정책 판단)의 두 화살표가 이 수업이 다루는 전부다 (p.3).

## 이 수업의 6단계 작업 모델

문제 정의 → 증거 설계 → 데이터 확보 → **AI 위임 분석** → 로직 검증 → 주장.

여섯 단계 중 "AI 위임 분석" 한 단계만 AI의 일이고, 나머지 다섯은 사람의 일이자 이 수업이 가르치는 것이다. 다만 나머지 다섯 단계도 AI와 함께 진행한다 (p.17–19).

## 분석의 네 단계 (강의 진행 순서)

기술적(무슨 일이 일어났는가, 6–7주) → 진단적(왜 일어났는가, 9–10주) → 예측적(앞으로 어떻게 될까, 11–12주) → 처방적(무엇을 해야 하는가, 13주). 뒤로 갈수록 정책 결정에 가까워진다 (p.20).
