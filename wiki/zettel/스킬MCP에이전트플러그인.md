## 왜 필요한가 — CLAUDE.md 의 한계

위키 규칙 같은 것은 CLAUDE.md 에 적지만, "월별 요약 만드는 절차"처럼 구체적인 작업 순서까지 거기 적으면 파일이 길어진다. 데이터를 매번 손으로 내려받는 일도 남아 있다 (03-스킬과MCP.pdf p.2). [[클로드코드기초]]에서 다룬 CLAUDE.md 하나만으로는 부족해지는 지점이다.

## 클로드 코드를 넓히는 네 가지

| 무엇 | 넓혀 주는 것 | 한 줄로 | 비유 — 주방 |
|---|---|---|---|
| ① 스킬 | 정해진 절차 | "이 작업은 이 순서로" | 레시피 카드 |
| ② MCP | 바깥 도구와 데이터 | "직접 가서 가져온다" | 주방 설비와 식자재 창고 |
| ③ 에이전트 | 일을 나눠 맡기기 | "따로 시키고 결과만 받는다" | 옆 조리대의 보조 요리사 |
| ④ 플러그인 | 앞의 셋을 묶어 배포 | "남과 나눠 쓴다" | 주방 전체를 담은 프랜차이즈 패키지 |

CLAUDE.md 가 "항상 이렇게"라면, 이 넷은 "필요할 때 이것을" (p.3).

## ① 스킬: 절차를 파일 하나로 묶는다

**쓰는 이유** — 같은 지시를 반복해서 붙여 넣는 상황. 절차를 CLAUDE.md 에 적으면 모든 대화에서 읽혀 비용이 든다 (p.4).

**만드는 방식** — 폴더 하나에 `SKILL.md` 하나. 폴더 이름이 곧 명령 이름이다. 앞머리(frontmatter)에 `name` · `description`, 그 아래 본문에 절차를 적는다. 길어지면 `scripts/`(매번 똑같이 돌릴 코드) · `references/`(필요할 때만 읽는 긴 문서) · `assets/`(결과물에 쓰는 서식·이미지)로 덜어 낸다 (p.4).

```
.claude/skills/인제스트/
  SKILL.md          ← 필수, 이 파일 하나면 스킬
    ---
    name: 인제스트
    description: raw/ 에 넣은 자료를 위키로 정리한다...
    ---
    1. wiki/index.md 를 먼저 읽는다
    2. 무엇을 만들지 먼저 말한다
    3. sources/ 와 topics/ 에 쓰고 index 를 갱신한다
```

**특징** — `description`이 언제 꺼낼지를 정하고, 본문은 꺼낼 때만 읽혀 길어도 평소에 비용이 없다 (p.4). 출처: anthropics/skills · skill-creator (2026.9.17. 확인).

### CLAUDE.md 와 스킬을 가르는 기준

| | CLAUDE.md | 스킬 |
|---|---|---|
| 담는 것 | 사실과 규범 | 절차 |
| 언제 읽히나 | 그 폴더의 모든 대화 | 그 작업을 부를 때만 |
| 길어지면 | 매번 비용이 든다 | 비용이 들지 않는다 |
| 예 | "면적 하한은 60㎡" | "월별 요약을 이 순서로" |

이미 불어난 CLAUDE.md 는 손으로 가르지 않는다 — `claude-md-management` 플러그인이 파일을 읽고 규범과 절차를 갈라 준다. `/claude-md-management:claude-md-improver`로 점검하고, `/claude-md-management:revise-claude-md`로 반영한다 (p.5).

### 스킬을 만들어야 할 때 — 세 가지 신호

1. 같은 설명을 두 번 이상 반복 (매번 같은 문단을 붙여 넣음)
2. CLAUDE.md 의 한 절이 절차로 자람 ("이 순서로"가 세 줄을 넘으면)
3. 손으로 되풀이하는 자동화 대상 (내려받기·이름 바꾸기·표로 옮기기)

다만 **세 번 넘게 할 일에만** 만든다 — 규격화에도 품이 든다. 처음부터 자동화하지 않고 먼저 손으로 반복해 본 뒤, 그다음 "찾는 일 자체"를 클로드에게 시킨다 — 지난 대화·커밋 기록에서 반복 패턴을 훑어 스킬로 만들 값이 있는지 판단하게 한다. 기록이 근거다, 머리로 고른 자동화 대상은 대개 빗나간다 (p.6).

### 어디에 두느냐로 범위가 갈린다

| 위치 | 범위 | 부르는 이름 |
|---|---|---|
| `~/.claude/skills/<이름>/SKILL.md` | 내 모든 프로젝트 | `/이름` |
| `.claude/skills/<이름>/SKILL.md` | 이 프로젝트 | `/이름` |
| `<플러그인>/skills/<이름>/SKILL.md` | 플러그인이 켜진 곳 | `/플러그인:이름` |

스킬은 두 가지로 불린다 — 내가 `/이름`으로 직접 부르거나, 클로드가 `description`을 보고 알아서 꺼낸다. 파일을 고치면 세션 중에도 반영되지만, 새 스킬 폴더를 처음 만들 때는 재시작이 필요할 수 있다. 출처: code.claude.com/docs/en/skills (2026.8.27. 확인) (p.7).

### 스킬을 만드는 스킬 — skill-creator

앤트로픽이 공개한 `skill-creator`를 가져다 쓴다. `/plugin`으로 설치하거나 `npx skills add https://github.com/anthropics/skills --skill skill-creator`로 폴더째 내려받는다. 시키면 ①무엇을 하는 스킬인지 되묻기 → ②SKILL.md 초안 → ③시험 프롬프트 2~3개 → ④쓴 결과와 안 쓴 결과 대조 → ⑤고쳐 쓰기 → ⑥description 다듬기(잘 꺼내지는지가 마지막 관문) 순으로 간다 (p.8).

## ② MCP: 바깥 도구를 꽂는 규격

지금까지는 공공데이터포털 → 사람이 내려받음 → 폴더에 넣음 → 클로드가 읽는 흐름이었다. MCP 로 붙이면 클로드가 MCP 서버·인증키를 통해 직접 가져온다 — **나르는 일이 없어지는 대신 확인할 일이 남는다** (p.9).

### 붙이는 법

```bash
# 원격 서버
claude mcp add --transport http <이름> <주소>
# 내 컴퓨터에서 실행하는 서버
claude mcp add <이름> -- <실행 명령>
# 범위 (기본값 local)
--scope local     # 나 · 이 프로젝트에서만
--scope project   # .mcp.json 으로 저장소에 함께
--scope user      # 내 모든 프로젝트
# 확인
/mcp
```

주소만 주고 "README 대로 붙여 줘, 인증키는 환경변수로"라고 시키면 클로드가 README 를 읽고 맞는 명령을 골라 실행한다 — 명령을 외울 필요가 없다. **인증키는 `.mcp.json` 에 적지 않는다** — 그 파일은 저장소에 올라간다 (p.10). 출처: github.com/chrisryugj/korean-law-mcp (2026.9.17. 확인).

### 기타 유용한 MCP

| 이름 | 무엇을 해 주나 | 비고 |
|---|---|---|
| QGIS | 레이어 추가·제거, 공간 처리 알고리즘 실행, 지도 렌더링 | 내 컴퓨터에서 도는 서버. QGIS 플러그인 + `uv` 필요 (github.com/jjsantos01/qgis_mcp) |
| KOSIS | 국가통계포털 통계표를 화면 없이 바로 조회 | 원격 · 시범 운영 · 인증키 없음 (kosismcp2026.vercel.app/api/mcp) |
| Playwright | 웹 브라우저 조작 — 페이지 열기·입력·수집 | 내 컴퓨터에서 도는 서버. Node.js 18+ |
| Context7 | 라이브러리 공식 문서를 현재 버전으로 찾아 읽음 | 원격 · 인증키 없이도 동작 |

QGIS MCP 의 `execute_code` 도구는 README 원문에 "Run arbitrary Python code in QGIS from Claude. Very powerful, but also be very cautious using this tool"라고 적혀 있다 — 내 컴퓨터에서 임의의 코드를 돌릴 수 있다는 뜻이며, 공개된 코드를 확인하고 붙이는 것이 전제다 (p.11).

### 붙였다고 믿지 않는다

| 조심할 것 | 왜 | 어떻게 |
|---|---|---|
| 아무 서버나 붙이지 않음 | MCP 서버는 내 자료를 읽고 바깥으로 보낼 수 있음 | 만든 사람과 공개된 코드를 먼저 확인 |
| 받은 것을 검사함 | 자동이 되면 이상해도 그대로 지나감 | 무엇을 보고 판정할지 미리 정해 둠 |
| 도구가 늘면 느려짐 | 붙인 서버의 도구 설명이 전부 컨텍스트에 들어감 | 쓰지 않는 서버는 꺼 둠, user/project 설치 구분 |
| 바깥이 바뀜 | 기관이 표의 칸 이름·단위를 바꾸면 오류 없이 빈칸이 넘어옴 | 받은 표의 자릿수·단위·빈칸을 사람이 확인 |

"두 번째(받은 것을 검사함)가 이 수업의 자리다 — 무엇을 검증할지는 사람이 정한다" (p.12). 출처: code.claude.com/docs/en/mcp (2026.8.27. 확인).

## ③ 에이전트: 따로 시키고 결과만 받는다

서브에이전트는 자기 대화창을 따로 가진 클로드다. 시킨 일을 그 안에서 하고 요약만 돌려준다. `.claude/agents/`에 두면 이 프로젝트, `~/.claude/agents/`에 두면 모든 프로젝트에서 쓴다 (p.13).

```
.claude/agents/wiki-checker.md
---
name: wiki-checker
description: 위키 페이지가 규칙대로 쓰였는지 검사한다...
tools: Read, Grep
model: sonnet
---
너는 위키 검사역이다. 고치지 말고 무엇이 잘못됐는지만 보고한다.
```

쓰는 이유 셋: 본 대화가 깨끗해짐(로그·검색 결과가 넘어오지 않음), 권한을 좁힐 수 있음(검사역에게 읽기만 줌), 여럿을 동시에 시킬 수 있음. `tools`로 쓸 수 있는 도구를 제한하는 것 — 검사역에게 쓰기 권한을 주지 않는 것이 요점이다 (p.13).

### 부르는 네 가지 방법

| 방법 | 어떻게 | 이럴 때 |
|---|---|---|
| 클로드가 알아서 | `description`에 "use proactively" 같은 문구 | 절차 안에 늘 끼는 일 |
| 이름을 말함 | "wiki-checker 에게 검사시켜 줘" | 이번 한 번만, 내가 알 때 |
| @ 로 못 박음 | `@agent-wiki-checker` — 반드시 그것이 돎 | 검사·채점처럼 빠지면 안 되는 자리 |
| 세션 전체를 맡김 | `claude --agent wiki-checker` 또는 settings.json 의 agent | 이 세션 내내 그 역할만 할 때 |

평소에는 첫째와 둘째로 충분하고, 빠지면 안 되는 자리에만 `@`로 못 박는다. 출처: code.claude.com/docs/en/sub-agents (2026.9.17. 확인) (p.14).

본 대화(①시킨다) → 작업 에이전트(②만든다) → 검사 에이전트(③검사, 읽기만) → 문제 있으면 ②로 되돌림 → 통과하면 본 대화에 ⑤요약만 온다. 오간 로그가 아니라 요약만 남는 것과, 검사 에이전트에는 읽기 도구만 주어 만든 쪽과 보는 쪽을 나누는 것이 요점이다 (p.15).

## ④ 플러그인: 묶어서 나눠 쓴다

스킬 · MCP 설정 · 에이전트를 한 폴더에 묶은 것이 플러그인이다. 혼자 쓸 때는 `.claude/`로 충분하고, 남과 나눠 쓰거나 버전을 붙이려 할 때 플러그인으로 만든다. `/plugin`으로 마켓플레이스에서 찾아 설치하고, 설치 후 반영이 필요하면 `/reload-plugins`. `claude-md-management` · `skill-creator`가 그 예다 (p.16).

```
my-plugin/
  .claude-plugin/plugin.json   ← 이름·설명·버전 (이 안에는 이것만)
  skills/<이름>/SKILL.md
  agents/                       ← 에이전트 정의
  hooks/hooks.json
  .mcp.json                     ← MCP 서버 설정
```

시험: `claude --plugin-dir ./my-plugin`. 출처: code.claude.com/docs/en/plugins (2026.8.27. 확인).

## 언제 쓰지 않을 것인가

한 번 하고 말 일에 스킬을 만들고 MCP 를 붙이고 루프를 짜면 손해다. **기준은 하나 — 반복하는가.** 세 번 넘게 할 일이면 규격화가 이기고, 아니면 그냥 시키는 게 빠르다 (p.17).

## 실습 개요 — 도구를 붙이고, 붙이기 전과 견주기

도착점은 같은 질문에 도구가 있을 때와 없을 때가 어떻게 다른지 화면으로 남기는 것 (p.19).

1. **도구 없이 먼저 물어본다 (0:00–0:15)** — 청주시 제1종일반주거지역 다세대주택의 건폐율·용적률 상한과 근거 조문·시행일을 묻고, 답을 그대로 `답-도구미사용.md`로 저장. 법령 이름·조 번호·숫자·시행일에 표시해 둔다. 법은 범위만 정하고 실제 숫자는 지자체 조례에 맡기므로, 학습해서 아는 것과 찾아서 아는 것이 갈리는 지점이다 (p.20).
2. **MCP 둘을 붙인다 (0:15–0:45)** — `korean-law`(법제처, open.law.go.kr 에서 무료 인증키 발급 후 `/plugin marketplace add chrisryugj/korean-law-mcp` → `/plugin install korean-law@korean-law-marketplace`)와 `kosis`(국가통계포털, 인증키 없이 `claude mcp add --transport http kosis https://kosismcp2026.vercel.app/api/mcp`)를 붙인다. `/mcp`에서 둘 다 Connected 확인 (p.21).
3. **같은 질문을 토씨 하나 바꾸지 않고 다시 한다 (0:45–1:15)** — 결과를 `답-도구사용.md`로 저장하고, 법령 이름·조 번호·조례를 보았나·시행일·숫자가 같은가 다섯 줄로 비교. 조례를 보지 않은 답은 범위만 말하거나 다른 지자체 숫자를 말한다. 도구가 있다고 늘 맞는 것은 아니다 — 조 번호가 여전히 틀릴 수 있다 (p.22).
4. **첫 답의 인용을 검증한다 (1:15–1:30)** — `korean-law`의 `verify_citations`로 실존·부존재·확인 불가를 가른다. 남는 시간에는 한 질문(부설주차장 기준 + 청주시 인구 추이)에 두 MCP 를 동시에 써 본다 — 클로드가 질문을 나눠 맞는 도구로 보낸다 (p.23).

## 과제 — 나만의 스킬 만들기

무엇을 스킬로 할지는 **기록이 정한다**: ①지난 2주간 세션 기록에서 반복 패턴 찾기 → ②세 번 넘게 한 일 중 가장 값이 큰 것 하나 고르기 → ③skill-creator 로 만들기(되묻기→초안→시험 프롬프트→고쳐 쓰기) → ④부르지 않고도 꺼내지는지 확인. 채점 기준 셋: 반복의 근거가 있는가(기록에서 찾았는가), 사실이 아니라 절차인가(사실이면 CLAUDE.md 자리), 스스로 꺼내지는가(description 이 "언제 쓰는지"를 말하는가). 마감 2026-10-02 (p.24).

## 확인 필요

- `korean-law` MCP 의 `verify_citations` 도구가 정확히 어떤 판정 로직(법령 DB 매칭 방식)을 쓰는지는 강의노트에 상세히 나오지 않음 — 원본 저장소(github.com/chrisryugj/korean-law-mcp) 확인 필요.
- QGIS MCP · KOSIS MCP · Playwright MCP · Context7 의 실제 설치 안정성(버전 호환 등)은 강의노트가 "명령과 화면은 버전마다 달라진다"고만 명시 — 각 공식 저장소 최신 문서 확인 필요.
